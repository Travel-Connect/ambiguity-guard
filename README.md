# run-ambiguity-guard

雑・曖昧なプロンプトのまま Claude Code が長時間実装に入るのを防ぎ、
実装前に認識合わせ（対象特定・計算仕様・検証基準）を行って出戻りを防止する skill。

## 目的

- 「いい感じに直して」「ここの文言変えて」のような曖昧な依頼で、勝手な推測のまま
  長時間実装に入らない。
- 実装判断・UI 対象・計算ロジック・検証観点に影響する不明点は実装前に必ず確認する。
- ただし過剰に質問しない。軽微な不明点は仮定を短く明示して進む。
- 確認した仕様・置いた仮定・追加したテストを最後に報告する。

## 使い方

1. Claude Code に依頼を投げる。依頼が曖昧（対象・仕様・検証方法が読み取れない）で
   長時間実装に入りそうな場合、この skill が自動適用される。
2. skill は Clarification Gate（8 観点）で判定し、
   A. Proceed（仮定明示で進む）/ B. Ask before proceeding（実装前に質問）/
   C. Stop and request artifact（スクリーンショット・期待値等を要求）のいずれかを出す。
3. B / C の場合、回答・資料を渡すと、確定仕様・仮定・検証予定が提示される。
   承認すると実装が始まる（承認前に実装は始まらない）。
4. 実装後は、確定した仕様・仮定・変更箇所・追加テスト・確認結果が報告される。

## 自動発火しない場合の手動呼び出し

```
/run-ambiguity-guard この画面の料金表示を直して
```

または依頼文に「認識合わせして」「出戻り防止で進めて」「仕様を確認してから実装して」
と書くと明示起動できる。

## 期待される挙動

- 曖昧な依頼 → 実装前に `[BLOCKING]` 付きの質問（優先度順・原則 1 ラウンド・最大 4 問・
  選択肢または推奨案付き）か、必要物の要求が出る。
- B / C の質問時は、`html-report` skill の確認フォーム（選択肢＋「送信」ボタンの 1 枚 HTML）で
  問いが出る。ユーザーは HTML で選んで送信するだけ（2026-11-04 に報告と質問の HTML を html-report に一本化）。
- 明確な依頼 → 止まらずに進む。仮定がある場合のみ `[ASSUMPTION]` が短く付く。
- 計算ロジックの依頼 → 丸め・税・期間・期待値・突合方法のいずれかが確認される。
- 突合データがある依頼 → 「突合した検証結果と一致すること」がテスト項目に追加される。

## Chrome / ブラウザスクリーンショット連携についての注意

- **この skill 自体はブラウザ操作ツールを新規に導入するものではない。**
- Claude Code 環境に Claude in Chrome / Chrome DevTools MCP / Playwright MCP /
  Browser MCP などが既にある場合はそれを使い、スクリーンショット付きで
  「ここのことですか？」と確認する。
- なければ、画面上の文言・URL・DOM セレクタ・コンポーネント名・ファイル名による
  **テキストでの対象特定にフォールバック**する（機能は落ちるが運用は変わらない）。

## 評価方法

- skill-creator が使える場合は `evals/evals.json` を実行する。
  should_trigger 6 件（曖昧な依頼で止まって質問するか）と
  should_not_overblock 4 件（明確な依頼で過剰に止めないか）を含む。
- 手動評価する場合は、新しいセッションで以下のようなプロンプトを投げ、
  期待動作と比べる:
  - 「この画面のここの文言をいい感じに直して」
    → 実装前に UI 確認フォーマット（この箇所のことですか）が出れば合格。
  - 「src/components/Header.tsx のタイトルを 'Dashboard' から 'Admin Dashboard' に
    変更して」→ 質問なしで進み、[ASSUMPTION] が短く付けば合格。

## 構成

```
run-ambiguity-guard/
├── SKILL.md                        # 運用ルール本体（Gate・質問・フォーマット）
├── checklists/
│   ├── ui-confirmation.md          # UI 対象特定の詳細チェックリスト
│   ├── calculation-logic.md        # 計算仕様の確認観点と突合方法
│   └── test-alignment.md           # 認識合わせをテストに落とす手順
├── examples.md                     # 発火例・非発火例の実例集
├── evals/evals.json                # 評価用テストケース
└── README.md
```

## 参考: 入力待ちの通知について

長時間作業中に Claude Code が「ユーザー入力待ち」になったことを OS 通知したい場合は、
skill ではなく Claude Code の hooks（Notification hook）を組み合わせるのが向いている。
hook の導入は本 skill のスコープ外のため、必要なら別途設定すること。
