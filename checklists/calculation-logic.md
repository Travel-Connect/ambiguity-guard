# 計算仕様の確認チェックリスト（calculation-logic）

計算ロジックの曖昧さを実装前に潰すための確認観点一覧。
SKILL.md「5. 計算ロジック確認」の詳細版。

## 1. 確認観点（実装前に全項目を走査する）

### 金額・数値

- [ ] 入力値の**単位**（円 / 千円 / %、個数 / 泊数 / 人数 等）
- [ ] **税込 / 税抜**のどちらで受け取り、どちらで返すか
- [ ] **税率**（複数税率・軽減税率・変更時期の扱い）
- [ ] **手数料**（率か固定額か、どの時点で引くか）
- [ ] **割引**（適用順序: 割引→税か、税→割引か）
- [ ] **上限 / 下限**（キャップ・最低金額の有無）

### 端数処理（丸め）

- [ ] 四捨五入 / 切り上げ / 切り捨て のどれか
- [ ] **小数第何位**で丸めるか（整数円か、小数 2 位か）
- [ ] **明細ごと**に丸めるか、**合計後**に一度だけ丸めるか（結果が変わる最頻出ポイント）
- [ ] 負数の丸め方向（-0.5 はどちらへ行くか）

### 期間・日付

- [ ] 日割り / 月割り / 期間按分の方式（実日数か 30 日固定か）
- [ ] **タイムゾーン**（UTC / JST、DB 保存時と表示時）
- [ ] **日付境界**（0:00 と 23:59、チェックイン日基準か宿泊日基準か）
- [ ] **締め日**（月末締め / 15 日締め、締め日当日を含むか）
- [ ] 開始日 / 終了日の**含み方**（両端含む・片端のみ・イベント境界）

### 異常系・データソース

- [ ] null / 空文字 / 0 / 負数 の入力時にどうするか（エラーか 0 扱いか）
- [ ] 既存仕様との互換性（既存レコードの再計算が必要になるか）
- [ ] 表示値と保存値の差（丸め前を保存し表示だけ丸める、等）
- [ ] **DB 値・API 値・画面表示値のどれを正とするか**

## 2. 期待値との突合方法

1. 期待値の**出所**を確定する（CSV / DB / 画面表示 / 帳票 / ログ / ユーザー提示値）。
2. 期待値と同じ入力を用意し、現行実装（または手計算）で再現を試みる。
3. 一致しない場合、差額から原因を推定する（丸めタイミング差はたいてい数円、
   税計算差は数 % 相当、期間按分差は日数比になる）。
4. 推定した仕様を**推奨案としてユーザーに確認**する（勝手に採用しない）。
5. 確定した期待値は、そのままテストケースにする（→ `checklists/test-alignment.md`）。

## 3. 実装前質問テンプレート

```
[BLOCKING] 計算ロジックの確認です。

対象: <機能名/ファイル/関数>
現状の理解:

* 入力: <input>
* 出力: <output>
* 現在の計算: <分かる範囲>
* 不明点: <不明点>

確認したいこと:

1. <質問>
2. <質問>
3. <質問>

推奨:
<コード・既存データ・画面表示から見て妥当な案>

この前提で実装してよいですか？
```

質問は上記観点のうち**結果が変わるものだけ**に絞る（全観点を機械的に聞かない）。
既存コード・既存データから確定できる観点は質問せず、確定根拠
（ファイル名・行番号・期待値）を添えて仮定または事実として提示する。
